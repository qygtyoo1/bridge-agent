# 权限面清单 · 白盒基线（T4）

> 目的：把「白盒」从口号变成可核对的清单——工具到底读什么、写什么、绝不做什麼。
> 对照方式：逐条可实测（文件/网络/字段），任何新增能力必须先更新本清单。

## 一、读取（Read）
| 对象 | 何时 | 范围 |
|---|---|---|
| 你显式提供的 JSON 文件（agent-card / appeal / handshake / room / ledger） | 运行 validate_sb / match_peers / peer_register 时 | 仅该文件内容 |
| 你显式提供的对方 agent-card URL | peer_register 核验时 | 仅该 URL 的公开响应（含其 endpoint 回读） |
| 本地账本（peers.jsonl 等） | 追加/读取匹配时 | 仅该文件 |

**不读**：环境变量、密钥、浏览器数据、其他目录文件、任何未显式指定的路径；不做端口扫描、不做内网探测。

## 二、写入（Write）
| 对象 | 内容 |
|---|---|
| 本地账本/结果 JSONL | 你的核验与匹配记录（默认本地私有，随你处置） |

**不写**：系统目录、注册表、其他项目文件；不静默创建后台服务。

## 三、网络（Network）
- 出站仅限：①你提供的 URL；②你在安装/更新时指定的 raw 地址；
- **零回传**：无遥测、无统计上报、无心跳；不使用第三方分析 SDK；
- **零服务器**：工具不托管任何中继/账号体系，握手为双方点对点（或由双方自行选择的通道）。

## 四、语义（Semantics）
- 协议不预设业务目标、不内置行业词表；capabilities / 诉求类型 / 共识字段由开发者自定义；
- 匹配打分规则完全公开（match_peers.py 可读），可替换/扩展。

## 五、人牵线（Human-in-the-loop）
- 握手必须双方 human_approval.present=true（validate_sb 强判）；
- 工具不提供「自主发现陌生人」能力，不做主动外呼。

## 六、自检方式（任何人可复现）
1. 断网跑 validate_sb / match_peers：应完全可用（仅 peer_register 需要网络）；
2. 用抓包工具观察：除你给的 URL 外应无出站请求；
3. 审阅全部源码：本仓库体积小、无压缩混淆、无第三方运行时依赖。
